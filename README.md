## 线路优化

方案参考 [CFNext](https://github.com/PAICNI/CFNext) 的公开做法：优选池优先于随机地址、下发前测活、保底节点前置、IPv6 默认不占名额、头部轮换避免所有客户端挤在同一个 IP。代码是按当前 cfnew 订阅流程单独写的。

每次生成订阅时按这个顺序组节点：

1. **保底**：沿用内置实测地址，固定 443，名字是「保底」，排在列表最前。
2. **实测优选**：拉取带延迟和速度的优选列表，电信 / 联通 / 移动可按面板筛选，延迟低的靠前。
3. **地区池**：香港、台湾、日本、新加坡、美国、韩国各取一小批。面板选了单个地区时只拉该地区，德国也可以单独选。
4. **兜底**：上面拿到的可用地址太少时，才从低延迟网段随机补一批，数量不超过下发上限的 20%，并继续测活。
5. **域名**：只保留少量能解析的优选域名，放在 IP 后面。
6. **测活**：最多探测 24 个地址，并发 4。探测全失败时整份照常下发，避免探测本身故障把订阅清空。
7. **裁剪**：默认最多 36 个。IPv6 默认不下发；选「仅备胎」时少量 IPv6 排到末尾；选「等权混合」时和 IPv4 交替。
8. **轮换**：保底和前 8 个优选地址每 5 分钟错开一位，客户端更新后不会总打到同一个入口。

填写了自定义优选 IP 时，默认只下发这些地址加上保底节点。打开「自定义节点合并默认池」后，才会再并入地区池。

外部列表缓存 30 分钟。缓存过期仍先用上一份，后台再刷新；连续拉取失败时，6 小时内继续用最后一份成功结果。订阅响应头 `X-Opt` 会带上本次数量和缓存状态。

面板里的开关在「线路优化」。也可以用环境变量 `OPT`、`OPT_LIMIT`、`OPT_PROBE`、`OPT_BALANCE`、`OPT_ANCHOR`、`OPT_MERGE`、`V6_POLICY`、`OPT_REGION`、`OPT_POOL`。

自动同步只覆盖 `_worker.js`。同步脚本解压后会执行 `node scripts/apply-route-optimizer.mjs`，把这套逻辑重新打进去。补丁对不上新版本时，同步会停住，仓库里仍是上一份已经优化过的代码。
